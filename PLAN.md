## How to run

```bash
npm install          # from the repo root (npm workspaces)
npm run dev          # starts apps/web on http://localhost:5173
npm run build        # typecheck + production build
npm run typecheck
npm run check:words  # rule R05: fails if user-facing copy uses a banned phrase
```

The public landing page is at `/`. The prototype launcher at `/apps` links to every app (with its sign-in and sign-up pages), the component gallery and the shared outputs. Every screen that has alternate states (empty, offline, error…) shows a small **States** control in the bottom-left corner; states can also be set with `?state=<name>` in the URL. Demo controls can be hidden from the launcher.

Visual QA (local Chrome via playwright-core, no browser download):
- `node scripts/shot.mjs --mobile --desktop [--dark] /path:name` takes screenshots. `--segments` captures long pages one viewport at a time (headless Chrome wraps full-page captures taller than ~8,000 px); `--scroll=px` and `--click="css|css"` open menus or sheets first. `SHOT_DIR` sets the output folder; `SHOT_DEMO='{"investorPersona":"marcus"}'` preloads demo state.
- `node scripts/contact-sheet.mjs <dir> <prefix> <out.png> [cols] [tileWidth]` tiles screenshots into one image for a quick review.

## Decisions (read before changing structure)

| # | Decision | Why |
|---|---|---|
| D1 | One Vite + React 19 + TypeScript app in `apps/web` holds the Owner App, Expert Desk, Command Center, Investor Portal, public site, passport PDF, notification templates, system pages and component gallery, each under its own route prefix and lazy-loaded as a separate chunk. | The docs call for five independently deployed apps on one design system. Route-level code splitting keeps each app's bundle separate now; each prefix can move into its own deployable when a backend exists. |
| D2 | The repo root is an npm workspace. The Field App will be `apps/field` (React Native / Expo) in Phase 9. Tokens and sample data move into `packages/` then. | UI PRD §2 specifies native Android for the Field App. |
| D3 | Stack: Vite 8, React 19, TypeScript (strict), Tailwind CSS v4, Radix primitives wrapped shadcn-style in `src/ds/ui`, Lucide icons, Recharts, MapLibre GL, vaul (bottom sheets), sonner (toasts), zustand (demo state), react-router. | Matches the master prompt's stack. shadcn components are written into the repo (that is how shadcn works) instead of generated by its CLI. |
| D4 | **Mobile-first everywhere, with a native-app feel.** Every app is fully usable at 360 px: bottom tab bar + "More" sheet, top app bar with back navigation, bottom sheets instead of side drawers, tables collapse to card lists, 44–48 px touch targets on phones, safe-area insets, `100dvh`, no tap flash, pressed states, view transitions, installable PWA. | Explicit request. **This overrides UI PRD §8's breakpoint table**, which limited the Expert Desk, Command Center and Investor Portal to read-only or partial views on phones. Desktop density rules (compact 32 px rows etc.) apply from 768 px up. |
| D5 | Design tokens are exactly those in UI PRD §5 / master prompt, as CSS variables with light and dark themes. The layout feel (floating sidebar, bento cards, pill segmented tabs, stat strips, kanban, GIS layer and properties panels) takes cues from the reference screenshots supplied by the user. | Tokens are specified; layout was left open. |
| D6 | No backend. All data is the fictional sample data from the prompts doc (Assets A, B, C, people, investors), extended with a few extra fictional assets so lists and boards are realistic. Actions update in-memory demo state and show a toast. | Prototype. |
| D7 | Maps use MapLibre with local GeoJSON only (boundaries, roads, rivers, settlements, protected areas, simulated imagery). No external tiles or images. | The master prompt says "no external images". Real basemap and imagery sources are a backend-phase task. |
| D8 | Owner App strings are externalised (English + Swahili dictionaries). Swahili is a draft and **must be reviewed by a native speaker** before launch (UI PRD §8). Other apps are English-only per UI PRD §2; their strings are not yet externalised (tracked in Phase 8). | |
| D9 | The launcher lets you choose the persona per app (Owner App: Peter Ouma or Grace Wanjiku; Investor Portal: Rachel Kim or Marcus Bell). | The sample data gives different screens to different personas. |
| D10 | **`/` is the public marketing landing page** (X-03 Home), written for the three audiences (licence holders, US investors, experts and field verifiers) with a CTA for each. The prototype launcher moves to `/apps`. | Requested by the user (25 Sep). Copy follows UI PRD §9: calm, factual, no banned words, nothing about specific assets, deals or returns, no investor sign-up, no testimonials. |
| D11 | **Every app has dedicated sign-in and sign-up pages** on one shared auth layout. The Owner App has a real public sign-up (phone and SMS code). For the Investor Portal, Expert Desk and Command Center, sign-up means accepting an invitation, because M01-2 forbids a public sign-up route; their sign-up URLs explain this and send people to the right request channel (Talk to SSD, Apply to the network, ask Platform operations). | Requested by the user, reconciled with M01-2. |

### Where things live

```
apps/web/src/
  ds/            design system: tokens.css, ui/ (primitives), components/ (20 signature components), shell/ (app shells), icons/
  data/          typed fictional sample data
  lib/           formatting, i18n, demo state store, hooks
  apps/owner/    OA-xx screens
  apps/expert/   ED-xx screens
  apps/command/  CC-xx screens
  apps/investor/ IP-xx screens (each app folder also has <App>Auth.tsx: sign-in, sign-up, invitation)
  auth/          shared auth layout (AuthLayout.tsx) and flows (flows.tsx: CredentialSignIn, InvitationGate)
  site/          X-03 public site: SiteLayout (nav, footer, phone action bar), Landing (/), audience pages, forms.tsx, parts.tsx
  outputs/       X-01 passport PDF, X-02 notifications, X-04 system pages
  gallery/       0.2 component gallery
  launcher/      /apps index
```

Screen files are named by screen ID, e.g. `apps/owner/OA03Home.tsx`.
